# 路线图

每个阶段都以「小步提交、随时可运行」为约束；标 ✅ 的是 v0.1 已完成的。

## v0.1 — 可用的第一版 ✅

- ✅ IR：文档模型、序列化、校验、遍历、示例文档
- ✅ 引擎：32 种内置积木 + 动态函数调用块、注册表、解释器（中止/事件流）、能力桥接口
- ✅ 编辑器：工具箱、拖拽吸附、嵌套、属性面板、变量面板、控制台、问题面板、撤销重做、自动保存
- ✅ i18n：中英文界面与运行时消息、语言包对齐测试
- ✅ 文档：架构、IR、积木、i18n、快速开始
- ✅ 测试：40 个用例覆盖 IR/engine/i18n/编辑器核心逻辑

## v0.2 — 语言能力（已落地）

- ✅ 等待积木（秒级、可被停止中断）
- ✅ 函数定义/调用/返回（画布 hat、参数作用域、动态调用块）
- ✅ 列表与字典字面量与常用操作，变量支持对应类型
- ✅ 「跳出循环」与本机文件操作（读写/存在/删除/列表，能力桥 + localStorage/桌面真实文件）

## v0.3 — 编辑体验

- 框选与多选、复制/粘贴/克隆子树（`cloneBlock` 已就绪）
- 从画布拖出积木到工具箱删除、拖拽跨越多个脚本
- 画布缩略图/概览
- 键盘导航与可达性（焦点环、屏幕阅读器标签）
- 属性面板内联校验提示（端口类型不匹配即时高亮）

## v0.4 — 更多语言能力

- ✅ `for each` 遍历列表（`对每项 x 在 列表:`）、`list.remove`（`移除(list, i)`)
- ⬜ `dict.remove`、遍历字典
- 自定义事件（broadcast / when I receive）
- 导出为可读文本（IR → 缩进式伪代码），验证「一份语义多种视图」

## v0.5 — 桌面壳与系统能力

- [x] 跨文件导入：`导入[文件]` / `从[文件]导入[函数]` / `从[文件]导入[函数]作为[名称]`

- ✅ Tauri 2 + Rust 壳，加载 `apps/editor/dist`
- ✅ `HostBridge` 的 Rust 实现：`fs.read/write/exists/delete/list`，直接访问本机文件系统（绝对路径 / `~/…` / 主目录相对路径）
- ⬜ 更多能力：`net.fetch`、`proc.spawn`、`clipboard`
- ⬜ 桌面端构建流水线（Linux/macOS/Windows），当前只配置 deb

## v0.6 — 插件体系

- 插件清单（manifest）：额外积木、额外能力、额外语言包、图标主题
- 发布/安装流程（本地目录、后续 registry）

## v0.7 — 自举

- ✅ 文本原语：`文本长度` / `取字符` / `子串` / `查找` / `拆分为列表` / `字符码` / `码转字符`，全部按 Unicode 码点
- ✅ 解析器：函数调用实参保留参数作用域，带参数的递归调用可写、`printNblk` → `parseNblk` 保真
- ✅ 函数局部变量（`创建局部变量` / `设置局部变量`），递归各层独立
- ✅ `并且` / `或者`（短路）、`对每项`、`移除`、`解析JSON`、`参数()`（命令行参数）
- ✅ nblk1：`bootstrap/nblk1.nblk` 是 IR 解释器，`bootstrap/tests/*.nblk` 与原生引擎逐行一致（`pnpm bootstrap:check`）
- ⬜ nblk1 直接解析 `.nblk` 文本（目前输入是 `tools/ir-dump.mjs` 导出的项目 IR）
- ✅ L2：nblk1 解释 nblk1 自身并继续解释 demo，输出与直接解释逐行一致（`pnpm bootstrap:self`）；为此把解释器标识符按 `nblk1_` 前缀分函数命名，避免自举时与程序变量同名覆盖；三层嵌套（1.33 亿步、约 2 分 20 秒）亦输出正确
- ⬜ 视性能决定是否把默认实现切换为自举版本

## v1.0 — 稳定

- IR 与插件 API 语义化版本冻结，附迁移工具
- 性能：大文档增量渲染、解释器性能基准
- 文档全量英文化、教程与示例项目
- 可访问性与国际化验收（RTL、日期/数字格式）
