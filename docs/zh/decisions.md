# 设计决策记录

记录会影响语言与工具行为的决定，以及做出这些决定的原因。新决定追加在末尾。

## 下标统一从 0 开始

**决定**：所有"位置"类的值一律从 0 开始计数。

- 「拆分文本取第几段」的下标是 0 起：`拆分("a,b,c", ",", 0)` 得到 `"a"`。
- 列表的读取/写入下标是 0 起（本来如此，现在与文本保持一致）。
- 「重复并计数」把当前轮次写成 0..N-1，而不是 1..N。

**原因**：之前文本分段是 1 起、列表是 0 起、循环计数是 1 起，同一种"位置"有三种口径，写程序时很容易错一位。Nexus Blocks 的目标是让用户从图形积木平滑过渡到普通编程语言，而主流语言（C、Python、JavaScript、Rust、Go）的数组下标都从 0 开始，循环也从 0 计数。统一成 0 起后，只有一套需要记住的规则。

**影响**：旧程序里 `拆分(..., 1)` 的含义从"第一段"变成"第二段"，需要注意（本项目在 V1.0 前不保留兼容，见下）。

## 不设置运行限制，也不规划权限面板

**决定**：解释器不再限制循环步数、递归深度、导入深度、文件大小、路径长度、命令输出长度、函数参数个数与积木可扩展项数；编辑器撤销历史也不设上限。原路线图中的「能力权限面板」「插件沙箱白名单」一并移除，不再规划。

**原因**：Nexus Blocks 的目标是与其他通用编程语言一致——程序能做什么，由用户的代码和操作系统权限决定，语言本身不替用户判断"跑太久了""文件太大了"。用户写死循环、递归爆栈、写出几个 GB 的文件，后果由用户自己承担（按「停止」、改代码、或让操作系统拒绝）。半吊子的运行时配额既拦不住真正恶意的程序，又会在正常程序上误伤：一次大数据处理就可能撞上 100 万字符的文件上限，一次深度递归就被 64 层截断。

**代价**：死循环不会自动报错，需要用户主动停止；过深递归会以引擎栈溢出（`RangeError`）结束，而不是一条友好的错误信息。这是刻意的取舍。

**边界**：浏览器版的文件"工作区"仍是扁平键空间，路径里不允许 `..` 这类段（那里没有目录的概念）；桌面与 CLI 直接使用真实文件系统，没有这个限制。
